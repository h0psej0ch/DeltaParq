\section{Methodologies}

\subsection{RO1}

The implementation of the storage and conversion structure will consist of multiple parts.
The basis of the system will be decomposing the current schema into a volatile and non-volatile 
table. Both tables will include the primary key of the original table such that they can be linked.
After decomposition a compression and retrieval interface for the non-volatile table 
will be created. For the compression interface, the input must be able to handle the current 
daily Parquet storage format that OpenINTEL uses while the output will result in a set of 
snapshot and delta structures. For the retrieval interface the program shall first use the 
volatile table to find all present primary keys. The interface shall then use the compressed set 
of snapshots and delta structures created by the accompanying compression interface to reconstruct 
the data for all the supplied primary keys.

\subsection{RO2}

Once the storage structure and conversion has been defined, the measurement framework can be 
built. The framework will be created such that it can handle a current OpenINTEL dataset as 
its input and will be able to use the created conversion methods to compress the dataset. 
Based on the resulting size of the compressed data, the framework will determine a compression 
score. Furthermore, the framework will be created such that it can use the compressed dataset 
and the retrieval interface to execute analysis functions and based on the time it takes to 
execute the analysis functions produce an analysis score.

\subsection{RO3}

To ensure proper testing of different delta-compression strategies, multiple instances 
of the interfaces for compression and retrieval must be implemented for different strategies. 
The framework from RO2 can then be used to analyze the performance of the strategies 
using supplied datasets from the OpenINTEL project.
